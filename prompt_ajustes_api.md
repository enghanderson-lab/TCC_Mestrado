Revise a API FastAPI recém-implementada em `src/video_search/api/` (commit "Adiciona API FastAPI para o Video Search Engine (Beta 1)") e corrija os seguintes pontos técnicos identificados em code review:

1. **Cancelamento de job de indexação é cosmético.** Em `api/routers/index.py`, `DELETE /index/{id}` (`cancel_job`) apenas marca `job.status = "cancelled"`, mas a thread em `_index_worker` continua rodando `run_index()` até o fim e, ao terminar, sobrescreve incondicionalmente para `job.status = "done"` — apagando o cancelamento e desperdiçando GPU/CPU. Implemente cancelamento cooperativo real: adicione um `threading.Event` (ou flag equivalente) ao `IndexJob`, passe-o para `run_index()` via o callback `on_progress` (ou um novo parâmetro `should_cancel`) para que o loop de indexação verifique periodicamente e interrompa o processamento se o cancelamento foi solicitado, e faça `_index_worker` checar `job.status == "cancelled"` antes de sobrescrever para `"done"`.

2. **`CameraDB` abre/fecha uma conexão SQLite nova a cada chamada.** Em `api/camera_db.py`, o método `_connect()` cria e destrói uma `sqlite3.connect()` por operação, serializado por um `threading.Lock` global — overhead desnecessário por request. Refatore para usar uma conexão persistente com `PRAGMA journal_mode=WAL` e `check_same_thread=False`, seguindo o mesmo padrão já usado em `indexing/embedding_cache.py` (conexão por thread via `threading.local()`, lock só nas escritas).

3. **CORS inseguro/quebrado em produção.** Em `api/main.py`, o default é `allow_origins=["*"]` combinado com `allow_credentials=True` — essa combinação é rejeitada pelos navegadores por especificação (CORS não permite wildcard de origem junto com credentials), então isso falha silenciosamente em produção se `VS_CORS_ORIGINS` não for configurado explicitamente. Ajuste o default para uma lista vazia seguindo fail-safe (ou levante um warning claro no startup se `VS_CORS_ORIGINS` não estiver setado e `allow_credentials=True`), e documente no README que `VS_CORS_ORIGINS` deve ser configurado explicitamente com a origem do frontend (ex.: domínio do Lovable) antes de qualquer deploy real.

4. **Scripts em `scripts/` continuam com imports quebrados.** Desde a refatoração em subpacotes (`models/`, `media/`, `indexing/`, `utils/`), os 10 scripts em `03_codigo/scripts/` ainda importam dos caminhos antigos e planos (ex.: `from video_search.vlm_describer import ...`, `from video_search.siglip_embedder import ...`, `from video_search.frame_extractor import ...`, `from video_search.multi_index import ...`, `from video_search.pipeline import ...`, `from video_search.config import ...`, `from video_search.hf_utils import ...`, `from video_search.embedding_store import ...`). Atualize todos para os caminhos corretos (`video_search.models.vlm_describer`, `video_search.models.siglip_embedder`, `video_search.media.frame_extractor`, `video_search.indexing.multi_index`, `video_search.indexing.pipeline`, `video_search.utils.config`, `video_search.utils.hf_utils`, `video_search.indexing.embedding_store`) e rode cada script para confirmar que executa sem `ModuleNotFoundError`. Isso é crítico para a reprodutibilidade dos números citados no README.

Não mexer em autenticação/usuários por enquanto — a API key única via `VS_API_KEY` deve continuar como está; hierarquia de papéis e tokens por usuário ficam fora de escopo por ora.

Ao final, rode a suíte de testes existente (`pytest`) para garantir que nada quebrou.
